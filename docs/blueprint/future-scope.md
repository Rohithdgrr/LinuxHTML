# Future scope

## Near term
Reliable local filesystem (directories, binary files and revisions); maintained guest; desktop shell; beginner lessons; keyboard accessibility; backup and restore; automated cross-browser regression testing.

## Medium term
Developer project templates, Git workflows, language toolchains, richer editor, package support, lesson authoring, local progress, carefully scoped network access and local observability. Measure startup, memory and storage use on real devices before promising targets.

## Long term
Optional accounts and synchronization, classroom assignments, organization workspaces, SSO, audit logs, deployment policies, extensions, additional languages and managed services. These require explicit privacy, authorization, threat-model and cost decisions.

## Research, not commitments
Alternative emulators or remote execution; collaborative editing; secure enclave-style isolation; native companion integrations; improved mobile support. Each must be assessed for licensing, browser constraints, operational cost and accessibility.

## Explicit limitations
Browser APIs do not provide unrestricted hardware, unlimited storage, complete offline reliability or a replacement for the host OS. Browser storage may be removed by users or evicted. Enterprise features cannot be implemented securely with a static frontend alone.
